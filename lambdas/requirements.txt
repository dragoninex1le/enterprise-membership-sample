# PORTH-613 — the Director, and with it the authorizer-context parse, credential
# scoping and permission diagnostics this app used to reimplement.
# 0.0.13 is a floor, not a preference, and the comment has to say WHICH facts
# make it one — a version number with a stale justification beside it is worse
# than a bare pin, because it invites someone to reason from the wrong reasons.
#
#   0.0.11  verification went LOCAL. The document carries each key's public half
#           and the receiver checks ECDSA-P256 itself, so the template grants no
#           kms:Verify at all.
#   0.0.13  a service is ONE document at services/{service_id}, carrying its
#           status, its addresses and its keys, and each key names the ALIAS its
#           owner signs with rather than a kid. The template reads services/* as
#           a prefix.
#   0.0.14  ServiceClient passes the call's DIRECTION to the endpoint resolver.
#           Without it every call resolves the default address, and this app
#           depends on the other one: ffug's document points the response
#           direction at porth-sample-app-callback, so on 0.0.13 every
#           completion would be delivered to ffug's own request ingress.
#   0.0.15  a completion is addressed to the verified `source_service` of the
#           request being completed, and CallbackDeclaration no longer carries
#           a service_id.
#   0.0.16  the REQUESTER supplies its callback address; the registry holds
#           none. CallbackDeclaration takes (operation, endpoint) and
#           ServiceClient.call accepts a supplied endpoint. This app passes
#           both; on 0.0.15 the endpoint is an unexpected argument.
#
# An older porth-common against this install would call KMS with no grant, look
# under signing-keys/* for documents that no longer exist, deliver its callbacks
# to the wrong function, and refuse the declaration this app now makes.
porth-common>=0.0.17
